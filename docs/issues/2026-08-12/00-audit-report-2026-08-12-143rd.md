## Source audit — surfaced F118 (non-atomic file writes)

Targeted pass over the carried-forward queue (R-142-3): items re-verified at
source; **the top two (fs-safe write atomicity) were confirmed as a real
correctness/reliability defect and minted as a new finding, then fixed**:

- **F118 (bug, P2): non-atomic file writes in `scripts/fs-safe.js`.**
  `safeWriteFile` (line 78) wrote directly via `fs.writeFile` — a crash or
  failed write mid-stream leaves a torn/corrupt file (`writeCsv` →
  `data/schools.csv`, sitemap XML, robots.txt, styles.css, search artifacts all
  funnel through it). `fastWriteFile` (line 122) **unlinked the target before
  writing** — a window where the file does not exist (readers see ENOENT) and a
  failed write loses the old file entirely (used for every one of the 3474+
  bulk page writes). **Fixed in this run** — both now write to a unique
  same-directory temp file (`<path>.tmp-<pid>-<seq>`) then `rename` over the
  target (atomic on POSIX); temp file is best-effort removed on failure. Added
  4 regression tests (no `.tmp-` leftovers on success; cleanup + IntegrationError
  when rename fails against a directory target). Post-fix: full suite
  1101/1097 pass; coverage 95.27/92.95 (up from 95.21/92.93); eslint 0/0;
  prettier clean; build PASS. **Merged via PR #682.**
