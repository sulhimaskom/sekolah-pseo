## Source audit — footer CURRENT_YEAR (last reachable queue item, P3)

Targeted pass over the queue item carried from R-143-4/R-144-4 ("footer CURRENT_YEAR
module-capture staleness, footer.js:13"). Analysis:

- `CURRENT_YEAR = new Date().getFullYear()` is a **hoisted module constant**
  (footer.js:13) evaluated once when the Node process loads the module.
- In this repo, the footer module is loaded **only inside batch build CLI runs**
  (`node scripts/build-pages.js` and test runners) — a process that starts and
  exits within seconds. Module-load time == render time == build time. For a
  static site, the copyright year **should** reflect the build year; page content
  is frozen at build time by design (F018's 23-day-old dataset demonstrates this).
- Render-time evaluation would produce **identical output** in every real
  execution path. The only scenario where capture-time differs from render-time
  would be a long-lived server process holding the module across a year boundary —
  this repo has no server runtime (static generator, `docs/blueprint.md` ADR
  0003/0006).
- **Verdict: non-defect for this architecture; P3 queue item DEFERRED** — no
  change is warranted and performing one would be a speculative refactor, which
  the contract forbids ("No speculative refactors"). The footer test
  (footer.test.js:13) already evaluates the year dynamically, so test stability is
  unaffected.
