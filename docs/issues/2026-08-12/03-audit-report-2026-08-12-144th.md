## Source audit — F032 minted in 38th run, RESOLVED this run

Targeted pass over a carried-forward queue item (R-143-4 "sitemap lastmod —
generation date, not data date, sitemap.js:93/100"). Re-confirmed at source and
**fixed**:

- **F032 (chore→bug, P2): sitemap `lastmod` non-determinism.**
  `collectUrlsFromSchools` (sitemap.js:87-114, pre-fix) stamped
  `const now = new Date().toISOString().split('T')[0]` on **every** URL —
  homepage, every province page, every school page. Consequences: (1)
  **non-deterministic output** — an unchanged dataset produces a different
  sitemap on every build run (daily churn, `git diff` noise, cache-busting);
  (2) **misleading freshness signal** — search engines are told every page was
  "modified today" when the underlying data was last updated 23 days ago (F018).
  Sitemap standard (sitemaps.org) defines `lastmod` as the date of last content
  modification, not sitemap generation.
  **Fixed in this run** — `lastmod` is now derived from the data's own
  freshness field (`updated_at`, stamped by ETL at etl.js:106, present in the
  CSV header per data-schema.js:149): aggregate pages (homepage, province)
  carry the newest `updated_at` across records; school pages carry their own
  record's `updated_at`; falls back to the generation date only when no record
  carries `updated_at` (legacy/test datasets). Preserves the
  `IntegrationError('schools must be an array')` contract by hoisting an
  explicit `Array.isArray` guard ahead of the new `.map()` call. Added 3
  regression tests (aggregate newest-date, per-school date, fallback format).
  Post-fix: sitemap 34/34 · full suite 1104/1100/0/4-skip · coverage 95.28/
  93.03 (up) · eslint 0/0 · prettier clean · build PASS. **Merged via PR #684.**
