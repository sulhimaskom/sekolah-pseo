## NEW Finding 014 — Parallel Test-File Race on Shared `dist/` (FLAKY TEST)

**Category**: test
**Priority**: P2
**Status**: valid (confirmed this run)

### Description

`node --test scripts/*.test.js` runs test **files in parallel**. Two files share the
global `CONFIG.DIST_DIR`:

1. `scripts/build-pages.test.js:44-59` — `test.before()` hook runs
   `fs.rm(CONFIG.DIST_DIR, { recursive: true, force: true })` (deletes the **entire
   shared dist/** directory) plus `fs.rm(.build-manifest.json)`.
2. `scripts/build-orchestrator.test.js:178-198` — `prepareBuildEnvironment`
   integration test writes `index.html` / `schools.json` into that **same** dist/ and
   asserts they exist after `await sharedPagesPromise` (line 190: `assert.ok(indexExists,
   'index.html should exist after sharedPagesPromise resolves')`).

**Race**: if `build-pages.test.js`'s `before` hook deletes `dist/` between
`build-orchestrator.test.js`'s `safeWriteFile(dist/index.html, …)` (BuildOrchestrator.js:417)
and the `fs.access()` assertion (line 186-190), the assert fails with `ERR_ASSERTION`.

### Empirical Evidence (this run)

```
RUN1 EXIT=0 pass=1026 fail=0
RUN2 EXIT=1 pass=1025 fail=2   ← flake reproduced
RUN3 EXIT=0 pass=1026 fail=0
RUN4 EXIT=0 pass=1026 fail=0   (coverage gate)

not ok 17 - prepareBuildEnvironment
  error: '1 subtest failed'
not ok 3 - scripts/build-orchestrator.test.js
  failureType: 'testCodeFailure'
  error: 'index.html should exist after sharedPagesPromise resolves'
  code: 'ERR_ASSERTION'
  expected: true
  actual: false
```

### Root Cause

`build-pages.test.js:50` (`fs.rm(CONFIG.DIST_DIR, {recursive:true})`) races with
`build-orchestrator.test.js:186-190` (access-assert on the same path) because
`node --test` (default) parallelizes across files and both use the **global** dist/,
not the per-test `TEST_TEMP_DIR` used elsewhere in build-pages.test.js.

### Affected Files

- `scripts/build-pages.test.js:44-59` (destructive shared-state `before` hook)
- `scripts/build-orchestrator.test.js:178-198` (shared-state integration assertions)

### Suggested Fix (for ISSUE MANAGER MODE / Phase 2)

Make at least one side use an isolated directory (e.g., point `CONFIG.DIST_DIR` at a
temp dir via env override, or run `build-orchestrator.test.js` with
`--test-concurrency=1`, or have build-pages' `before` hook only clear its own temp
outputs). Lock with a regression test that runs the two files concurrently N times.

### Impact

- CI flakiness: 1 of 4 fresh runs failed this session; intermittent in prior runs too
  (previously mis-attributed to finding 001).
- Blocks deterministic "all checks green" merge criteria from the operating contract.
