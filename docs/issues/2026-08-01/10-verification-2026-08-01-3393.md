**NEW CRITICAL FINDING (F015) — OS command injection in `scripts/fetch-data.js`**,
empirically verified end-to-end this run (was NOT among the prior 14 findings):

- `validateRepoUrl()` (`fetch-data.js:55-97`) claims in its own docstring to
  "prevent command injection" but only checks protocol, hostname, and `.git` suffix.
  Shell metacharacters (`$`, `;`, `|`, `&`, backtick) **survive URL parsing** — Node's
  `URL` class leaves `$()`, `;`, `&`, `|` unencoded in `pathname`.
- `execGitCommand()` (`fetch-data.js:140-153`) runs the reconstructed URL through
  `execSync(command, ...)` which executes via `/bin/sh -c` — command substitution runs.
- **PoC verified**: `--source 'https://x.invalid/$(touch$IFS/tmp/opencode/pwned3).git'`
  passed `validateRepoUrl` (ends with `.git`, valid hostname) and created
  `/tmp/opencode/pwned3` via the `$(...)` substitution inside `execSync`.
- **Attack surface**: `--source` CLI argument (`fetch-data.js:327-330`) and any caller
  of `fetchFromGitHub(repoUrl)` (`:164`). Default repo constant is hardcoded & safe;
  the vulnerability triggers on **untrusted/operator-supplied repo URLs**. If this
  script is ever driven by config-file, webhook, or workflow input, it is RCE.
- **Severity**: P1 security (HIGH). Requires attacker control of the URL argument, but
  the sanitizer's stated purpose is defeated and the failure is silent.
- **Fix**: use `execFileSync('git', ['clone', '--depth', '1', url, dir])` with an
  argument array (no shell), or whitelist URL chars to `[A-Za-z0-9._~:/%#@!$&'()*+,;=.-]`
  minus `$`/backtick, or pass `{ shell: false }`.
