### 2.1 Finding 001 — ESCALATION (new evidence this run)

Prior diagnosis: "floating promise can exit before fetch completes."

**Fresh empirical evidence proves the defect is deterministic and functional:**

1. `scripts/fetch-data.js:164` `fetchFromGitHub()` returns
   `fetchCircuitBreaker.execute(...)` (`scripts/resilience.js:289` — **`async`**),
   so `fetchFromGitHub` returns a **Promise**.
2. `scripts/fetch-data.js:338` — `main()` is **sync** (`function main()` line 319)
   and calls `const csvPath = fetchFromGitHub(sourceRepo);` **without `await`**.
   `csvPath` is therefore a Promise object.
3. `scripts/fetch-data.js:339` `copyToRaw(csvPath, outputPath)` →
   `fs.copyFileSync(sourcePath, destPath)` (line 285).
4. **Live test**: `fs.copyFileSync(Promise.resolve('/tmp/x'), '/tmp/y')` throws
   `ERR_INVALID_ARG_TYPE: The "src" argument must be of type string or an
   instance of Buffer or URL.`
5. `copyToRaw` catches → returns `false` → `main()` throws
   `IntegrationError('Failed to copy external data...')` → catch block →
   `useCachedData()` → **always falls back to cached data**.

**Net effect**: `npm run fetch-data` (and `npm run etl`'s fetch path) can *never*
use freshly fetched data — every run silently degrades to stale cache when a
cache exists, or terminates if none does. The defect is masked in CI because
the build uses the committed `data/schools.csv`, and `fetchFromGitHub` is only
tested for argument validation (fetch-data.test.js:229-243), never for its
return-value contract.

**Recommendation**: `main()` must be `async` and `await fetchFromGitHub(...)`;
add a unit test asserting `fetchFromGitHub` resolves to a string path and that
`main()` awaits it. Severity: **P1** (functional break of a documented feature —
`npm run fetch-data` / ETL refresh path).
