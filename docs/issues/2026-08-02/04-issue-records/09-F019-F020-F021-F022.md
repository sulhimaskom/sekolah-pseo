## F019 — Dead / unreachable code in tests/run_tests.py

> **Labels**: `refactor`, `P3`

### Summary

`tests/run_tests.py` contains two maintenance hazards:

1. **Duplicated import block** (lines 15–25): `time`, `traceback`, `argparse`, `typing`
   are imported twice (the second import block `import sys, json, time, traceback, argparse`
   at lines 19–25 repeats the first at lines 1–14).
2. **Unreachable code** (lines 523–527): a `return suite` at line ~522 is followed by a
   second, dead `print("Running Data Validation Tests...")` + `run_data_validation_tests(suite, root)`
   + `return suite` block that can never execute.

### Evidence

- `sed -n '15,30p' tests/run_tests.py` → duplicate imports
- `sed -n '515,530p' tests/run_tests.py` → unreachable block after `return suite`

### Impact / Risk

Low severity but real: duplicate imports confuse readers; the unreachable block suggests a
botched merge left dead code that could mislead maintainers into thinking an extra test pass
runs. Determinism of the Python harness is unaffected (both blocks return the same suite),
but it is a correctness-of-intent defect.

### Suggested resolution

- Remove the duplicated import block (lines 19–25).
- Delete the unreachable block after the first `return suite`.
- Add `python3 -m py_compile tests/run_tests.py` or a lint step to catch dead code.

## F021 — Orphaned security gate: check-workflow-security.js

> **Labels**: `security`, `P2`

### Summary

`scripts/check-workflow-security.js` (233 lines) is a CLI security scanner (shebang + argv +
3× `process.exit`) that reports the F013 violations, but:

1. It is **NOT in package.json scripts** — no `npm run` entry.
2. It has **NO test file** (`check-workflow-security.test.js` missing) — the only module
   besides `head-meta.js` without one.
3. **Its failures are suppressed** in `.husky/pre-commit`:
   `node scripts/check-workflow-security.js 2>/dev/null || echo "⚠️ ... skipped"`.
   Because the `|| echo` swallows the exit code, **the security gate can never block a commit**,
   while F013 violations (2 CRITICAL + 10 HIGH) persist across 6+ runs.

### Evidence

- `ls scripts/check-workflow-security.test.js` → missing
- `.husky/pre-commit` → `node scripts/check-workflow-security.js 2>/dev/null || echo ...`
- `node scripts/check-workflow-security.js` → 12 violations (2 CRITICAL + 10 HIGH)

### Impact / Risk

Medium-high: the project's only automated guard against workflow-permission regressions
(F013) is effectively inert. The exact regressions it was built to catch have now re-surfaced
6+ times while the gate prints a warning and exits 0.

### Suggested resolution

1. Add `check-workflow-security` to package.json scripts.
2. Add a unit test for the scanner's violation detection.
3. Change the pre-commit hook to **fail** on CRITICAL violations (exit non-zero) instead of
   `|| echo` swallow; allow warnings to pass with output.
