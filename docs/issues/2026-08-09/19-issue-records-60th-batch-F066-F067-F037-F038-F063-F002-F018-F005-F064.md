## Issue 1 — F066 (P1, test): pytest wipes real dist/ — ROOT-CAUSED (deterministic 2/2)

- **Category**: `test` / **Priority**: `P1`
- **Evaluation date**: 2026-08-09 (101st run)
- **Status**: **ROOT-CAUSED CONFIRMED — deterministic repro 2/2** (was LATENT ≈1/171)

### Summary

First new root-caused defect in 12+ runs. `tests/test_data_validation.py:70-88`
(`test_dist_directory_can_be_created`) computes the real project root via
`os.path.dirname(os.path.dirname(__file__))` and executes
`shutil.rmtree(dist_dir)` against the **real `dist/`** — both at test start
(lines 77-78) and teardown (lines 86-87). Running `pytest` after a build destroys
the build output deterministically.

### Root cause

The F052/F014 per-process temp-dir redirect (applied to the JS test files —
`build-pages.test.js:17-18`, `sitemap.test.js:13`) was **never applied to the Python
test suite**. `tests/test_data_validation.py` targets the real project directory
instead of an `os.tmpdir()` sandbox.

### Evidence

```
node scripts/build-pages.js  → dist/ EXISTS (sitemap-index.xml present)
python3 -m pytest tests/test_data_validation.py -q
ls dist/                      → No such file or directory  (2/2 runs)
```

### Impact / Risk

Any CI sequence that builds then runs `npm run test:py` (or `npm test`) silently
destroys `dist/` — downstream steps (deploy, link validation, artifact collection)
fail or emit stale artifacts. Remediation is a one-line test-isolation fix:
point `dist_dir` at a temp path like the JS tests do.
