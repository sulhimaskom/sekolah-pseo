## NEW observation this run — CI schedule-run regression (F063 aggravated)

The 149th ledger recorded F063 as "PR-event workflow runs land in `action_required`;
schedule runs pass". **That is no longer true.** This run's `gh run list` probe
(workflow `on-pull.yml`, last 12 runs) shows:

```
7 failure  (schedule)   — exit 124 (opencode timeout `timeout -k 1m 90m`)
5 success  (schedule)
1 cancelled (schedule)
1 in_progress
```

And the daily `oc - orchestrator` run (31657336809) FAILED at checkout:

```
##[error]fatal: could not read Username for 'https://github.com': terminal prompts disabled
The process '/usr/bin/git' failed with exit code 128
```

Root cause is deterministic and source-visible: `orchestrator.yml` uses
`secrets.GH_TOKEN` (lines 33/41) for checkout, but the repo's runtime token is
`secrets.GITHUB_TOKEN` — the workflow references a secret that does not exist in
the Actions environment, so checkout cannot authenticate. This is the F038
GH_TOKEN finding manifesting as an **actual live CI failure**, not just a static
lint violation. Same pattern drives the `pull` workflow's exit-124 timeouts (the
agent loops inside a 90-minute timeout when its PR-handler work cannot proceed).

Severity assessment: F038 (already security/P0) gains a concrete operational
impact; CI/CD health worsens. Recommendation: replace `secrets.GH_TOKEN` →
`secrets.GITHUB_TOKEN` in `orchestrator.yml` and `architect-agent.yml`, remove
`API_KEY` duplicates of `GEMINI_API_KEY` in `on-push.yml`/`parallel.yml`, and
drop `id-token`/`actions` write from non-merge workflows — then re-run
`node scripts/check-workflow-security.js` to green (F037/F038 resolution path).
