## F065 config resolution evidence (Phase 2, this run)

- `scripts/config.js` line 22: `normalized.startsWith(baseNormalized)` returned
  `true` for sibling-prefix paths — `validatePath('/project2', '/project')` →
  `true` (reproduced in-session via node eval) while the path is _outside_ the
  base directory. `path.resolve` normalizes `..` segments but does not defend
  against prefix siblings.
- Fix: after exact-match equality, require a path-separator boundary —
  `baseWithSep = baseNormalized.endsWith(path.sep) ? baseNormalized :
baseNormalized + path.sep`, then `startsWith(baseWithSep)`. `/project2`,
  `/project2/src`, `/project-extra` all → `false`; `/project/src`,
  `/project`, `/etc/passwd` (already false), `/project/../etc/passwd`
  (already false) unchanged.
- Regression tests: `scripts/config.test.js` — 3 new cases ("sibling-prefix
  escape (/project2 for base /project)", "nested sibling-prefix escape
  (/project2/src…)", "sibling-prefix with suffix (/project-extra…)").
