## F067 resolution evidence (Phase 2, this run)

- `.husky/pre-commit` line 3 (original): `node scripts/check-workflow-security.js
2>/dev/null || echo "⚠️ ... skipped"` — the `|| echo` swallows the check's
  exit code. Since the check exits 1 whenever any violation exists (12
  currently), the gate could never fail and the message misreported the check
  as "skipped".
- Fix: run the check in `--json` mode inside an `if output=$(...)` guard (safe
  under `sh -e`, husky's invocation), parse `totalViolations`, and:
  - `> 12` (documented baseline, held finding F037) → print regression warning
    and `exit 1` (commit blocked);
  - `<= 12` → print non-blocking status and continue;
  - parse failure → fail-open (`0`), never false-blocks.
- Verified: all 4 scenarios under `sh -e` (12 non-blocking, 13 BLOCKS, 0
  non-blocking, garbage non-blocking); `sh -n` syntax OK; `shellcheck -e
SC2148` clean (SC2148 pre-existing — no shebang by design, husky wraps with
  `sh -e`); full matrix green after fix (lint 0/0, build PASS, test:js
  1104/0/4, pytest 13/13, coverage above thresholds).
