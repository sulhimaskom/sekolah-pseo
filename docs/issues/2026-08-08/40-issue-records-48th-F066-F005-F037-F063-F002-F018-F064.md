## Issue 1 — F066 (P1, test): dist-destruction flake — LATENT (1 wipe / ≈75 cycles)

- **Category**: `test` / **Priority**: `P1`
- **Evaluation date**: 2026-08-08 (89th run)
- **Status**: **LATENT — re-observed once, unreproducible in sustained loop**

### Summary

During the first `rm -rf dist && npm run build && node --test scripts/*.test.js` cycle the
entire `dist/` directory was observed missing afterward (`ls dist/` → ENOENT). 74 subsequent
cycles (full suite ×57, targeted trio ×5, serial ×2) all preserved `dist/sitemap-index.xml`.
No in-session trigger reproduced the wipe, so per the FAIL-SAFE rule **no root-cause guess
is recorded**. Prior ledger claims ("clean 14th / FIXED 4/4") computed on small samples are
demoted to "latent — 1 seen" with an honest ~1.3% observed rate.

### Evidence

```
Early cycle: rm -rf dist && npm run build && npm run test:js
  → ls dist/ | grep sitemap → "No such file or directory"
Subsequent: 15-cycle loop → 15/15 sitemap-index.xml present (dist_id 164)
  + 25 more single cycles → 100% clean
Any one can destroy dist (sitemap + static), but no deterministic repro yet
```

Source: `scripts/*.test.js` parallel workers (F052/F066 pattern isolated most, not all).

### Impact / Risk

A test worker can wipe the build output that `npm run build` writes; in CI this surfaces as
missing `dist/sitemap-index.xml` in a follow-up step (not a failing test, so not caught by
the current gate). Risk: intermittent CI artifact loss. Latent.

### Suggestion (for a future Phase-2 candidate when reproduced)

If repro becomes a 1/15 rather than 1/75, guard `node --test` with exclusive temp
`CONFIG.DIST_DIR` redirection in every "integration-ish" test — the F052 pattern extended;
or hard-enforce a workload: run the build, then the suite, then assert artifacts survive.
