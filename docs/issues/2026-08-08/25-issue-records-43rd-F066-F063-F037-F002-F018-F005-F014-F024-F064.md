## Issue 1 — F066 (NEW, P1 → FIXED in-loop): sitemap.test.js destroyed real build artifacts in dist/

- **Category**: `test` / **Priority**: `P1`
- **Evaluation date**: 2026-08-08 (84th run)
- **Status**: **FIXED this run** (temp-dir redirect applied; verified sitemap survives)

### Summary
`scripts/sitemap.test.js` is the **only remaining test file** that writes to — and then
**deletes** — the real `CONFIG.DIST_DIR` (dist/) sitemap artifacts. The F052/F014 fixes
redirected `build-pages.test.js` (per-process temp ROOT_DIR+DIST_DIR) and
`build-orchestrator.test.js` (per-process temp DIST_DIR), but **sitemap.test.js was
missed**. Tests at lines 564–655 call `generateSitemaps()` (which writes real
`dist/sitemap-001.xml` + `dist/sitemap-index.xml` via the module-captured
`CONFIG.DIST_DIR`) and then delete them in "Cleanup" (`fs.rm`).

### Evidence (deterministic, 2/2 fresh repros this run)
```
RUN 1: npm run build  → dist/sitemap-index.xml + dist/sitemap-001.xml present
       npm run test:js → ls dist/sitemap-index.xml → "No such file or directory"
RUN 2: (identical sequence) → sitemap files again deleted after test:js
```
Source: `scripts/sitemap.test.js:578-591` (writes + cleanup), `:606-617` (cleanup),
`:650-654` (cleanup); no `CONFIG.DIST_DIR` override anywhere in the file (only the
line-667 test redirects a *local* copy to `testDir`). Confirmed via `git log`: the
cleanup lines pre-date the F052 fix; no later run redirected this file.

### Impact / Risk
- `npm test` (and CI test steps) destroys the sitemap files the build deterministically
  emits — contradicting the F024 "RESOLVED" claim in the presence of a test run.
- If any downstream step (deploy, validation, sitemap check) runs after tests, it sees a
  broken dist/. Same defect class F014/F052 were created to eliminate; this is its
  surviving instance. Not a race — a deterministic side effect.
- dist/ is gitignored, so no tracked corruption; blast radius is build-artifact integrity.

### Suggested fix (Phase-2 candidate, minimal/atomic)
Mirror the F052 pattern in `sitemap.test.js`: before requiring `./sitemap`, set
`CONFIG.DIST_DIR = path.join(os.tmpdir(), 'sitemap-test-' + process.pid)` (and point the
tests' assertions at that dir), or pass an explicit output dir to `generateSitemaps`.

### Resolution (this run)
**FIXED in-loop**: `scripts/sitemap.test.js` now redirects `CONFIG.DIST_DIR` to a
per-process temp dir (`sitemap-test-dist-${process.pid}`) immediately after loading
`./config`, mirroring the F052 pattern in `build-pages.test.js` /
`build-orchestrator.test.js`. Verified: `npm run build` → `npm run test:js`
(1056/1056 pass) → `dist/sitemap-index.xml` **survives** (previously deleted 2/2).
Prettier-clean; lint exit 0; coverage gate met (94.94% stmt).
