## Source audit — surfaced F116 (design-token contract violation)

Targeted pass over the R-140-2 queue (items were pre-identified; this run's job was
empirical confirmation). All queue items re-verified at source; **one was confirmed
as a real emitted-artifact bug and elevated to a minted finding**:

- **F116 (bug, P2): `--radius-full` CSS token consumed but never emitted.** The
  design contract is fully declared: `DESIGN_TOKENS.borderRadius.full = '9999px'`
  (design-system.js:94) and `styles.js` references `var(--radius-full)` in **4
  rules** (lines 175, 243, 699, 790 — pills, badges, primary button), but
  `getCssVariables()` emitted only `--radius-sm/md/lg` (design-system.js:171–173).
  Empirical proof in-session: `getCssVariables()` lacked `--radius-full:`;
  post-`npm run build`, `dist/styles.css` contained **4 `var(--radius-full)`
  references and 0 definitions** → `border-radius: var(--radius-full)` is an
  unresolved custom property → computed value is invalid → browsers fall back to
  `border-radius: 0` → pill/badge/button shapes render as squares (visual bug in
  every generated page). **Fixed in this run** (emit `--radius-full` after
  `--radius-lg`; regression assertion added to `scripts/design-system.test.js`
  `includes border radius variables`). Post-fix: `dist/styles.css` defines
  `--radius-full: 9999px` (5 refs = 1 definition + 4 usages); build PASS; full
  suite 1093 tests / 1089 pass / 0 fail; coverage 95.2/92.93; eslint 0/0;
  prettier clean on changed files. Merged via PR #678.
